# Wind codebase audit — 6 September 2026

Baseline: **7cdc4495c68c52a2a7d02702d52f86d368ae0653**, version **0.19.0**, before the implementation of this audit. Findings below describe that baseline. Current delivery status belongs to [the implementation plan](PLAN-AUDIT-2026-09.md).

This English repository edition preserves all 61 findings and the reconciliation of all 61 debt entries. The original French report has been retained as a separate user-facing artifact. References retain baseline line numbers in their labels; implementation may have moved those lines.

The foundations are sound: separate crates, transactional SQLite, action and sending journals, extensive tests, TLS verification, PKCE and isolated message rendering. Less-tested paths nevertheless contradict several guarantees: received HTML inside the editor, draft recovery, IMAP identity, ambiguous SMTP outcomes and cross-platform publication.

Prioritize **S01–S02, B01–B09 and B26**: confidentiality, content loss and duplicates precede structural cleanup. P1 means disclosure, destruction, content loss or incorrect sending; P2 means wrong behavior, availability or insufficient operational guarantees; P3 means maintainability or a planned improvement. Reproduced means a synthetic demonstration was run; static means the path was established by inspection, without a complete real-service scenario. Historical measurements and product decisions are explicitly distinguished from current failures.

## Security

### S01 — P1 — Received HTML can request inclusion of another local message

Baseline evidence: [sanitize.rs:52](../crates/mail-render/src/sanitize.rs), [compose.rs:341](../crates/mail-core/src/compose.rs), [commands.rs:3138](../apps/desktop/src/commands.rs), [commands.rs:3258](../apps/desktop/src/commands.rs).

Reproduced primitives; application chain established statically. Incoming `data-wind-transfert` survives sanitization and authorizes a body lookup/replacement at send time. The account comparison is insufficient: a sender can guess a same-account mailbox/UID, and a user replying with that quote may include unrelated content. This requires a valid reference and user sending; automatic exfiltration without interaction was not demonstrated.

**Solution:** strip incoming internal authority; retain necessary provenance separately in trusted draft metadata with account/mailbox/generation/UID. Preserve edited content and restore only surviving image references. **Validation:** forged incoming marker causes no referenced-message lookup and no unrelated outgoing content.

### S02 — P1 — Iframe CSS assumptions are unsafe in the main editor DOM

Baseline evidence: [sanitize.rs:122](../crates/mail-render/src/sanitize.rs), [Editor.svelte:104](../apps/desktop/ui-v2/src/Editor.svelte), [tauri.conf.json:21](../apps/desktop/tauri.conf.json).

Reproduced. String matching misses escaped `u\72l(...)`; Edge attempted the intercepted synthetic network request while the blocked-image counter was zero. Fixed positioning/inset/high z-index covered the 1280 px viewport. Rich paste also enters before application filtering. The iframe CSP does not protect citations inserted into the application's main document.

**Solution:** separate reading and editing policies; parse CSS, allow safe properties and values, prevent network resources and escaping layout, sanitize paste/drop before insertion. **Validation:** escaped/commented CSS corpus, zero unconsented requests, visible controls and preserved permitted formatting. [Ammonia's property filter](https://docs.rs/ammonia/latest/ammonia/struct.Builder.html#method.filter_style_properties) is a possible starting point, subject to value-policy tests.

### S03 — P2 — Development dependencies have security advisories

Baseline evidence: [package.json:9](../apps/desktop/ui-v2/package.json), [package-lock.json](../apps/desktop/ui-v2/package-lock.json), [dependabot.yml:5](../.github/dependabot.yml).

Confirmed by npm audit and upstream advisories: Vite 5.4.21, esbuild 0.21.5 and two transitively affected Svelte plugin packages. Four affected packages do not mean four independent product vulnerabilities. Conditions concern development servers and differ between advisories; no distributed-binary RCE was demonstrated.

**Solution:** upgrade Vite/plugins/lockfile together to compatible patched versions, add npm audit and automated dependency tracking; review major changes instead of forcing `audit fix`. **Validation:** advisories removed, build and startup journeys pass. Sources: [Windows fs.deny bypass](https://github.com/advisories/GHSA-fx2h-pf6j-xcff), [optimized sourcemap traversal](https://github.com/advisories/GHSA-4w7w-66w2-5vf9), [launch-editor NTLMv2 disclosure](https://github.com/advisories/GHSA-v6wh-96g9-6wx3), [esbuild cross-origin server access](https://github.com/advisories/GHSA-67mh-4wv8-2f99). The local configuration does not itself force network exposure.

### S04 — P2 — Size limits are checked after allocations

Baseline evidence: [commands.rs:4521](../apps/desktop/src/commands.rs), [mail-imap/lib.rs:768](../crates/mail-imap/src/lib.rs), [mail-imap/lib.rs:808](../crates/mail-imap/src/lib.rs).

Static. Attachment reads allocate the complete file before the 25 MB check; oversized received messages travel alone without an absolute bound, and batches accumulate their bodies. Fetching a single attachment downloads complete MIME.

**Solution:** inspect size and enforce the limit during the actual read, including file growth; cap individual and accumulated MIME allocations, process incrementally and address MIME parts directly. **Validation:** huge synthetic files/messages fail without proportional memory growth or blocking unrelated commands.

### S05 — P2 — Log privacy relies on every caller

Baseline evidence: [trace.rs:12](../apps/desktop/src/trace.rs), [trace.rs:33](../apps/desktop/src/trace.rs), [cycle.rs:572](../crates/mail-core/src/cycle.rs), [poll.rs:521](../apps/desktop/src/poll.rs).

Static. Free-text diagnostics can include remote errors, folder names, addresses or other personal data despite the message-free logging promise. Rotation does not remove those contents.

**Solution:** structured events, internal IDs, typed error categories and an allowlist of fields; separate user-facing detail from support traces; bound length and sanitize CR/LF. **Validation:** synthetic address/subject and injected newlines never appear in support logs.

## Reliability and behavior

### B01 — P1 — Ambiguous SMTP results are automatically retried

Baseline evidence: [mail-smtp/lib.rs:141](../crates/mail-smtp/src/lib.rs), [outbox.rs:579](../crates/mail-core/src/outbox.rs).

Reproduced at the outbox boundary: acceptance followed by a lost reply becomes transient/queued; two flushes produce two simulated deliveries. **Solution:** distinguish certain temporary/permanent refusal from unknown delivery; persist and quarantine uncertainty for reconciliation/user action. Message-ID is not SMTP idempotency. **Validation:** cut after DATA before the 250 reply; no automatic repeat after another cycle or restart. [RFC 5321 section 4.5.3.2.6](https://www.rfc-editor.org/rfc/rfc5321.html#section-4.5.3.2.6).

### B02 — P1 — Closing can lose text while reporting a saved draft

Baseline evidence: [Compose.svelte:620](../apps/desktop/ui-v2/src/Compose.svelte), [Compose.svelte:671](../apps/desktop/ui-v2/src/Compose.svelte).

Reproduced: save catches its failure, close hides the editor and reports success without a draft ID. **Solution:** propagate failure, retain editable content and permit retry; success requires persistence acknowledgement. Extend the guarantee to native-window closing. **Validation:** full disk, busy SQLite and IPC failure keep text recoverable and never announce success.

### B03 — P1 — Direct bodies/files do not verify UIDVALIDITY

Baseline evidence: [body.rs:19](../crates/mail-core/src/body.rs), [mail-imap/lib.rs:374](../crates/mail-imap/src/lib.rs), [commands.rs:1522](../apps/desktop/src/commands.rs), [commands.rs:4601](../apps/desktop/src/commands.rs).

Body reproduced; other paths static. A reused UID can return an unrelated new-generation body while the database still records the old generation. **Solution:** carry complete identity through network results and validate before consumption and commit; invalidate obsolete work across body, backfill, forward and attachment paths. **Validation:** reset between selection and fetch; no new-generation bytes attach to an old envelope.

### B04 — P1 — EXPUNGE fallback deletes other clients' marked messages

Baseline evidence: [mail-imap/lib.rs:623](../crates/mail-imap/src/lib.rs).

Static: without UIDPLUS, global EXPUNGE removes all Deleted messages, beyond Wind's requested UID. **Solution:** native MOVE where possible; otherwise defer unsafe purging and state the limitation. **Validation:** a server without UIDPLUS containing several clients' deleted UIDs only affects the requested scope.

### B05 — P1 — Remote draft import loses fields and files

Baseline evidence: [convert.rs:270](../crates/mail-imap/src/convert.rs), [poll.rs:185](../apps/desktop/src/poll.rs), [drafts.rs:558](../crates/mail-core/src/drafts.rs).

Static, extending D-19: the import retains To/subject/text/HTML but loses Cc/Bcc, files, priority and reply metadata. **Solution:** a complete draft model, conservative MIME round trip and atomic import of every retained part; no silent overwrite of unhandled content. **Validation:** external draft with Cc/Bcc, two files and References; editing one word preserves the functional contents.

### B06 — P1 — Conflict forks lose attachments

Baseline evidence: [drafts.rs:228](../crates/mail-core/src/drafts.rs).

Reproduced: the fork has zero files. **Solution:** transactionally fork the complete edited version and return its new file metadata. **Validation:** concurrent attachment changes and obsolete revision saves preserve each version's own files, including source-row replacement.

### B07 — P2 — A draft's changed sender is not persisted

Baseline evidence: [Compose.svelte:283](../apps/desktop/ui-v2/src/Compose.svelte), [drafts.rs:256](../crates/mail-core/src/drafts.rs).

Reproduced: UI selects account B but UPSERT retains account A. **Solution:** explicit atomic account transfer, files and old mirror tombstone included; reassess reply references. **Validation:** create under A, switch to B, close/restart; ownership, signature and mirror remain B.

### B08 — P1 — Forwarded text edits are undone when sending

Baseline evidence: [compose.rs:365](../crates/mail-core/src/compose.rs), [commands.rs:3168](../apps/desktop/src/commands.rs).

Reproduced, D-52: replacing the entire forwarded block restores text the user removed. **Solution:** retain the edited document and restore only surviving image references from safe metadata. **Validation:** a removed confidential sentence never appears in outgoing MIME.

### B09 — P1 — Enqueue and draft deletion are separate operations

Baseline evidence: [Compose.svelte:783](../apps/desktop/ui-v2/src/Compose.svelte), [Compose.svelte:817](../apps/desktop/ui-v2/src/Compose.svelte), [commands.rs:3240](../apps/desktop/src/commands.rs).

Static: a crash after enqueue leaves a reusable draft and may duplicate sending. **Solution:** a core transaction consumes the exact draft version while enqueueing, with a unique request ID for IPC retries. **Validation:** crash after commit before acknowledgement leaves one outbox request and no inadvertently reusable active draft.

### B10 — P2 — Late asynchronous responses can alter a new composition

Baseline evidence: [Compose.svelte:304](../apps/desktop/ui-v2/src/Compose.svelte), [Compose.svelte:640](../apps/desktop/ui-v2/src/Compose.svelte), [Compose.svelte:881](../apps/desktop/ui-v2/src/Compose.svelte).

Static: saves/file operations can adopt IDs or content after the visible session changes. **Solution:** capture an edit-session token across every operation, invalidate on close, ignore obsolete responses without losing their durable writes. **Validation:** hold an old save/file response, change composer, release; new-session fields remain intact.

### B11 — P2 — Reply-all does not consistently honor Reply-To

Baseline evidence: [commands.rs:3036](../apps/desktop/src/commands.rs).

Static: reply-all uses From, falling back differently when To is empty. **Solution:** shared core recipient logic using effective Reply-To first, then deduplication and own-address exclusion. **Validation:** differing From/Reply-To with To/Cc/aliases produces the intended recipients in both reply modes.

### B12 — P2 — Cc-only and Bcc-only messages are rejected

Baseline evidence: [compose.rs:63](../crates/mail-core/src/compose.rs).

Reproduced: validation requires To although delivery can have Cc/Bcc recipients. **Solution:** require a nonempty union of valid recipients, retaining blind-recipient privacy. **Validation:** both cases send through the synthetic transport; Bcc never appears in delivered headers.

### B13 — P2 — Image-only editing can be treated as empty

Baseline evidence: [Editor.svelte:129](../apps/desktop/ui-v2/src/Editor.svelte), [commands.rs:4298](../apps/desktop/src/commands.rs).

Static: textContent-based emptiness ignores meaningful nontext nodes. **Solution:** semantic content detection with correct untouched-value preservation. **Validation:** close/reopen/send an image-only body; image bytes/references survive.

### B14 — P2 — Resumed initial sync retains messages deleted between passes

Baseline evidence: [sync.rs:197](../crates/mail-core/src/sync.rs).

Reproduced: the deleted envelope survives initialization. **Solution:** reconcile against an authoritative UID inventory before declaring initialization complete. **Validation:** interrupt, delete remotely, resume; local inventory converges without losing pending intentions.

### B15 — P2 — Feed refresh retains stale pages and account scope

Baseline evidence: [Feed.svelte:55](../apps/desktop/ui-v2/src/Feed.svelte), [Feed.svelte:103](../apps/desktop/ui-v2/src/Feed.svelte), [App.svelte:1829](../apps/desktop/ui-v2/src/App.svelte).

Static: replacing page zero while retaining `cards.slice(PAGE)` preserves old-account or deleted cards. **Solution:** clear pages on scope change and reconcile loaded pages after mutation; preserve valid selection intentionally. **Validation:** several pages, quick account/filter changes and deletions produce no stale or mixed-scope cards.

### B16 — P2 — Old calendar cancellation can cancel a newer invitation

Baseline evidence: [store.rs:491](../crates/mail-core/src/store.rs), [store.rs:548](../crates/mail-core/src/store.rs), [mail-ical/lib.rs:129](../crates/mail-ical/src/lib.rs).

Reproduced: CANCEL sequence 1 cancels REQUEST sequence 2; organizer and recurrence identity are insufficiently considered. **Solution:** event/organizer/occurrence identity and explicit version policy. **Validation:** request/update/cancel permutations and recurrence exceptions preserve the newest applicable event state.

### B17 — P2 — Legacy OAuth migration overwrites a rotated refresh token

Baseline evidence: [mail-auth/lib.rs:191](../crates/mail-auth/src/lib.rs), [mail-auth/lib.rs:237](../crates/mail-auth/src/lib.rs).

Static: finish stores the new token, then legacy handling can write the old one over it. **Solution:** choose and persist one effective rotated token; remove legacy data only after successful persistence. **Validation:** inject a vault and rotation/persistence failures; the valid newest token survives restart.

### B18 — P2 — Manual browser fallback drops its OAuth listener

Baseline evidence: [flow.rs:132](../crates/mail-auth/src/flow.rs).

Static: BrowserFallback leaves a URL whose callback listener no longer lives. **Solution:** retain a cancellable consent session with a deadline across automatic/manual opening. **Validation:** automatic open fails, user opens the URL manually, callback still completes once.

### B19 — P2 — OAuth callback I/O can escape the flow deadline

Baseline evidence: [flow.rs:223](../crates/mail-auth/src/flow.rs).

Static: deadline checks cover idle acceptance, not unbounded/trickled line reads or writes; an incorrect state can abort the valid flow. **Solution:** absolute deadline, bounded request parsing and read/write timeouts; ignore unrelated callbacks within the deadline. **Validation:** slow/truncated/oversized/wrong-state callbacks terminate correctly without blocking a valid callback. This is local availability risk, not a demonstrated PKCE bypass; reqwest's existing 30-second blocking default is not this defect.

### B20 — P2 — Backfill budget counts successes instead of attempts

Baseline evidence: [backfill.rs:137](../crates/mail-core/src/backfill.rs).

Static: missing bodies can trigger work across the whole finite corpus despite the nominal budget. **Solution:** bound attempts, elapsed time and bytes, with a retry-aware cursor. **Validation:** repeated misses/errors stop within budget and eventually revisit eligible entries.

### B21 — P2 — Partial synchronization failures disappear from status/retry

Baseline evidence: [App.svelte:238](../apps/desktop/ui-v2/src/App.svelte), [App.svelte:589](../apps/desktop/ui-v2/src/App.svelte), [cycle.rs:617](../crates/mail-core/src/cycle.rs), [poll.rs:806](../apps/desktop/src/poll.rs).

Static: backfill errors are ignored/cleared, successful INBOX masks failures elsewhere, automatic retry relies on a global failure, and connection state becomes stale. **Solution:** durable per-account/folder partial status, typed failure/retry policy and connection reconciliation. **Validation:** mixed folder outcomes retain actionable errors and only retry eligible work.

### B22 — P2 — Queued mail is announced as sent

Baseline evidence: [Compose.svelte:805](../apps/desktop/ui-v2/src/Compose.svelte), [catalog.fr.js:283](../apps/desktop/ui-v2/src/lib/catalog.fr.js).

Static: success toast follows enqueue before SMTP acceptance. **Solution:** distinguish queued, scheduled, sent and unknown outcomes. **Validation:** offline enqueue, accepted send, rejected send and ambiguous result show truthful states.

### B23 — P2 — Non-CONDSTORE flags do not eventually converge

Baseline evidence: [cycle.rs:607](../crates/mail-core/src/cycle.rs), [sync.rs](../crates/mail-core/src/sync.rs), [DEBT.md:317](../docs/DEBT.md).

Static: a 500-recent-UID window and STATUS shortcuts can miss old changed flags forever. **Solution:** bounded rotating reconciliation with a maximum revisit delay, preserving local pending intent. **Validation:** mutate a flag outside the recent window and in a skipped folder; it converges within the declared bound.

### B24 — P2 — Generic credentials cannot be repaired in place

Baseline evidence: [commands.rs:379](../apps/desktop/src/commands.rs).

Static: deleting/recreating an account to change credentials risks local drafts/outbox data. **Solution:** edit and verify credentials/configuration without replacing account identity. **Validation:** password/server repair preserves local intentions and restores connection.

### B25 — P2 — Generic setup verifies IMAP but not SMTP

Baseline evidence: [commands.rs:500](../apps/desktop/src/commands.rs).

Static: setup may succeed for an account that cannot send. **Solution:** independently authenticate both protocols without delivering mail, with an explicit partial receive-only state if allowed. **Validation:** IMAP success/SMTP failure and the reverse produce accurate setup status.

### B26 — P1 — Failed instance locking still starts writers

Baseline evidence: [main.rs:257](../apps/desktop/src/main.rs).

Static: lock errors are logged but the application proceeds with write workers. **Solution:** fail closed or enter an explicit mode with no write/external effects. **Validation:** competing process and injected locking error never start a second sender or migration writer.

### B27 — P2 — Disk checks omit some announced writes

Baseline evidence: [cycle.rs:450](../crates/mail-core/src/cycle.rs), [cycle.rs:578](../crates/mail-core/src/cycle.rs), [backfill.rs:150](../crates/mail-core/src/backfill.rs).

Static: checks follow INBOX work and estimates count missing envelopes while omitting body/file backlog. **Solution:** maintain reserve and per-batch write budgets using known sizes; stop recoverably and prioritize local intentions. **Validation:** nearly-full synthetic disk with cached envelopes/missing bodies preserves drafts and resumes cleanly.

### B28 — P2 — Archive bypasses MOVE and can repeat COPY

Baseline evidence: [mail-imap/lib.rs:896](../crates/mail-imap/src/lib.rs), [mail-imap/lib.rs:943](../crates/mail-imap/src/lib.rs).

Static, distinct from B04: the non-atomic COPY/delete path is used even when MOVE is available; interruption after COPY can duplicate archives. **Solution:** share the safe MOVE primitive; record/reconcile fallback stages before repeating COPY. **Validation:** cuts at each stage do not accumulate archive copies.

### B29 — P2 — Release binaries can differ from their announced commit

Baseline evidence: [make-release.ps1:264](../scripts/make-release.ps1), [make-release.ps1:281](../scripts/make-release.ps1), [release-macos.sh:47](../scripts/release-macos.sh).

Static: Windows builds dirty sources then commits only version files; macOS does not require HEAD/tag equality. **Solution:** clean identified checkout, rejection of unexpected/untracked source, per-platform HEAD/tag proof and commit/lock/hash attestation. **Validation:** dirty source or wrong HEAD stops before build/upload; rebuild from the tag.

### B30 — P2 — Latest becomes public before the macOS matrix is complete

Baseline evidence: [make-release.ps1:307](../scripts/make-release.ps1), [release-macos.sh:131](../scripts/release-macos.sh), [verify-release.ps1:97](../scripts/verify-release.ps1).

Static: Windows publication precedes macOS assets/manifest; verification permits missing macOS assets. **Solution:** populate a draft release, verify the entire supported matrix, publish the complete manifest last, then promote Latest. **Validation:** interrupted uploads leave the previous public release complete.

### B31 — P2 — Release signature verification is incomplete and incorrectly decoded

Baseline evidence: [verify-release.ps1:174](../scripts/verify-release.ps1).

Static; format confirmed in installed Tauri sources. Missing minisign can yield an overall pass despite NOT PROVEN, and the Tauri base64 `.sig` wrapper is not decoded before minisign. **Solution:** decode correctly and require cryptographic proof for final validation; distinguish an explicitly incomplete structural mode. **Validation:** valid/tampered/wrong-key/missing-tool cases across four platforms. The application's updater itself verifies signatures; this finding concerns the proof script.

## Architecture and unnecessary complexity

### A01 — P2 — Business rules remain outside mail-core

Baseline evidence: [STANDARD.md:266](../docs/STANDARD.md), [commands.rs:2973](../apps/desktop/src/commands.rs), [commands.rs:3240](../apps/desktop/src/commands.rs).

Inspection contradicts the documented 100% core rule: reply/forward/send/invitation decisions remain in Tauri/JS. **Solution:** extract portable use cases incrementally while fixing those paths; shell resolves dependencies and converts DTOs, UI presents results. **Validation:** equivalent behavior can be tested without AppHandle/Tauri through every entry point.

### A02 — P2 — Global locking mixes interactive and heavy work

Baseline evidence: [commands.rs:4998](../apps/desktop/src/commands.rs).

`off_pump` serializes expensive files/CPU/queries behind a mutex; other workers use separate connections, so this is not global transactional exclusivity. **Solution:** move pure/file work out of critical sections, keep short SQLite transactions, bound/prioritize jobs; add readers only when measurements justify them. **Validation:** p95 gesture latency during backfill, file addition and indexing; no invented speedup.

### A03 — P2 — The blocking guard misses indirect helpers

Baseline evidence: [commands.rs:319](../apps/desktop/src/commands.rs), [commands.rs:339](../apps/desktop/src/commands.rs), [main-thread-guard.mjs](../e2e/main-thread-guard.mjs).

The text guard misses Store work through async `add_oauth_account` after an await. **Solution:** move Store access into the controlled blocking helper and enforce the boundary structurally. **Validation:** indirect forbidden call fails the guard; artificially slow Store access leaves the UI responsive. Native-window freezing was not measured during the audit.

### A04 — P2 — Types do not adequately express identity and ownership

Baseline evidence: [body.rs:19](../crates/mail-core/src/body.rs), [remote.rs](../crates/mail-core/src/remote.rs), [drafts.rs:256](../crates/mail-core/src/drafts.rs), [convert.rs:400](../crates/mail-imap/src/convert.rs).

Loose account/mailbox/UID tuples omit generation, draft ownership is weak, and attachment indices depend on MIME filtering. **Solution:** complete MessageKey, DraftKey and structural MIME-part references, validated at the core boundary; migrate previous references explicitly. **Validation:** wrong accounts, generation reset, MIME classification changes and schema versions cannot substitute content.

### A05 — P2 — Error strings drive behavior

Baseline evidence: [commands.rs:3030](../apps/desktop/src/commands.rs), [mail-imap/lib.rs:1032](../crates/mail-imap/src/lib.rs), [mail-smtp/lib.rs:116](../crates/mail-smtp/src/lib.rs), [lib/transport.js](../apps/desktop/ui-v2/src/lib/transport.js).

Strings/prefixes obscure network/auth/throttle/local-storage/uncertainty distinctions. **Solution:** typed codes, scope and retryability, separate unknown outcomes, UI localization and controlled diagnostic causes. **Validation:** decision matrix remains identical across language changes.

### A06 — P2 — Account removal does not cancel already-started work

Baseline evidence: [commands.rs:554](../apps/desktop/src/commands.rs), [commands.rs:4974](../apps/desktop/src/commands.rs), [poll.rs](../apps/desktop/src/poll.rs).

Captured jobs can continue after removal. `reset_sessions` already prevents account resurrection, so that older claim is not repeated. **Solution:** closing state/account generation, stop new jobs, quiesce or cancel existing work before purge; explicitly handle already-engaged SMTP delivery. **Validation:** hold transport, remove account, release; no orphan/new work and an honest delivery result.

### A07 — P2 — Database adoption depends on UI ordering and a path cache

Baseline evidence: [store/migrations.rs:563](../crates/mail-core/src/store/migrations.rs), [store/migrations.rs:788](../crates/mail-core/src/store/migrations.rs), [DEBT.md:72](../docs/DEBT.md).

Command access can bypass the intended adoption order; replacing a file at an initialized path can conditionally skip initialization. **Solution:** adopted-database handle, separate read-only probe, file-identity/version verification and cache invalidation. **Validation:** early commands, cancellation and replacement at the same path cause no hidden/skipped adoption.

### A08 — P3 — Large files combine several domains

Baseline evidence: [commands.rs](../apps/desktop/src/commands.rs), [store.rs](../crates/mail-core/src/store.rs), [App.svelte](../apps/desktop/ui-v2/src/App.svelte), [List.svelte](../apps/desktop/ui-v2/src/List.svelte).

Baseline commands.rs 6,206 lines, Store 2,956, App 2,172 and List 1,822; Store's 5,618 test lines are already separate. **Solution:** domain modules and focused controllers extracted alongside protected behavior. **Validation:** unchanged behavior and fewer cross-domain dependencies; no arbitrary line cap, SQLite replacement or repository framework is justified.

### A09 — P3 — Several duplications need small shared structures

Baseline evidence: [store.rs:2505](../crates/mail-core/src/store.rs), [store.rs:2565](../crates/mail-core/src/store.rs), [mail-smtp/lib.rs:348](../crates/mail-smtp/src/lib.rs), [store/migrations.rs:807](../crates/mail-core/src/store/migrations.rs), [DEBT.md:972](../docs/DEBT.md).

Pin/asides twins, list/screener/cleanup geometry, Feed/PaperTrail piles, positional SMTP parameters, duplicate foreign-key PRAGMA and shell/PowerShell gate lists remain. **Solution:** small internal enums, shared identical geometry, a named SMTP DTO, one PRAGMA per connection and a common gate manifest. **Validation:** both variants' tests, focused visual comparison and gate-step parity. Already-shared menus/mutex helpers should not be rebuilt.

### A10 — P2 — Structural tests miss end-to-end invariants

Baseline evidence: [.github/workflows/ci.yml:103](../.github/workflows/ci.yml), [e2e/package.json](../e2e/package.json), [ipc-contract.mjs](../e2e/ipc-contract.mjs), [mail-core/src/test_support.rs](../crates/mail-core/src/test_support.rs).

## Application objectives and missing guarantees

### G01 — P2 — Define the actual offline contract

Baseline evidence: [commands.rs:1522](../apps/desktop/src/commands.rs), [store.rs:1919](../crates/mail-core/src/store.rs).

Cached bodies do not imply files are available or search is complete. **Proposal:** explicit per-message/account availability and search coverage, bounded revocable offline retention, defined behavior when remote content disappears before download. **Acceptance:** disconnect after explicit preparation; announced content opens/searches/forwards without silent omissions.

### G02 — P2 — Extend zero-loss to controlled local recovery

Server mirrors do not reconstruct all drafts/outbox intentions, preferences, signatures and rules. **Proposal:** consistent SQLite/WAL backup/export/restore and retention policy; never export vault secrets in plaintext. **Acceptance:** restore a synthetic installation with files and pending sends without accidentally delivering them.

### G03 — P2 — Make keyboard accessibility a verified objective

Baseline evidence: [Compose.svelte:1022](../apps/desktop/ui-v2/src/Compose.svelte), [Settings.svelte:631](../apps/desktop/ui-v2/src/Settings.svelte), [List.svelte:1237](../apps/desktop/ui-v2/src/List.svelte).

Modal ARIA lacks focus containment; tabindex=-1 checkboxes and row key handling choose rather than toggle. **Proposal:** contain/restore focus, inert background, explicit selection keyboard vocabulary and useful screen-reader progress/error announcements. **Acceptance:** compose, setup, multiselect and act without mouse or involuntary modal escape.

### G04 — P2 — Define reversible deletion and image consent

Baseline evidence: [store.rs:1074](../crates/mail-core/src/store.rs), [store.rs:2640](../crates/mail-core/src/store.rs), [DEBT.md:902](../docs/DEBT.md).

Global rules/learned contacts intentionally survive account removal; the probe retains one derived contact. Per-message image consent cannot be revoked directly. **Proposal:** distinguish disconnect/local removal/forgetting derived data, track shared provenance, and add message-image revocation. **Acceptance:** no unexpected exclusively-owned remnants after synthetic removal, while shared active data survives; next open obeys revocation.

### G05 — P2 — Make performance budgets comparable

Baseline evidence: [STANDARD.md:236](../docs/STANDARD.md), [DEBT.md:10](../docs/DEBT.md), [DEBT.md:380](../docs/DEBT.md), [DEBT.md:600](../docs/DEBT.md).

These are not current measurements; opening definitions changed to threads. **Proposal:** version cold/warm p50/p95 protocols, corpus/network/architecture/session/process scope, interference, idle and post-close retention; date exceptions. **Acceptance:** comparable fixtures/protocols across releases before choosing optimization.

### G06 — P2 — Formalize the support and delivery proof matrix

Baseline evidence: [ci.yml:69](../.github/workflows/ci.yml), [release-macos.sh](../scripts/release-macos.sh), [DEBT.md:1142](../docs/DEBT.md).

Four distribution architectures have unequal native proof. macOS has both target CI builds but no WKWebView UI suite; Windows ARM also lacks sufficient native proof. **Proposal:** OS/WebView/architecture/install/update/vault matrix with dated evidence; plan signing/notarization before broadening simple-install promises. **Acceptance:** each supported platform has a complete artifact and installation/open/vault/update proof. ### G07 — P3 — Bound invitations and language consistency

Baseline evidence: [mail-ical/lib.rs](../crates/mail-ical/src/lib.rs), [DEBT.md:666](../docs/DEBT.md), [DEBT.md:1083](../docs/DEBT.md).
