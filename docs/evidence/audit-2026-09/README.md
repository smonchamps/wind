# Audit 2026-09 — preserved evidence

Evidence for the September 2026 audit that existed **only** under `target/` or
`.claude/worktrees/`, both excluded by `.gitignore` and both erased by routine
cleanup — `cargo clean` for the first, `git worktree remove` for the second. The
audit plans referenced those paths while the lots were still open, so a disk
cleanup would have destroyed the trace of measurements already committed.

Sources, measurements and reports are preserved here. Build caches, generated
corpora and binary outputs are not: they are reproducible from what is kept.

Placed under `docs/evidence/` rather than `docs/archives/`, which STANDARD §10
reserves for **closed-out** plans — the audit is still open.

## Language ratchet

`docs/evidence/` is exempt in `e2e/language-gate.mjs`, on the same ground as
`spikes/`: this material was written under that exemption, and lifting it out of
an ignored directory must not silently put it back under the ratchet.
Translating a measurement falsifies it. Without the exemption the gate reported
18 files above baseline, +316 markers.

## Re-running the lot 2 proof

`lot2-proof/` is a verbatim copy — its relative paths still point at the location
where it actually ran, two levels below the repository root. Restore it before
building, rather than editing the paths, so the archived sources stay identical
to the ones that produced the 3/3 results:

```bash
mkdir -p target/lot2-proof && cp -r docs/evidence/audit-2026-09/lot2-proof/. target/lot2-proof/ && cargo run --manifest-path target/lot2-proof/Cargo.toml
```

It builds against the live core source and the repository lockfile, uses the
core flush and two SQLite connections, and regenerates its own `fixture-*/`
SQLite databases. Its two unused-code warnings come from the standalone
inclusion of the instance module and are not a gate failure.

## Regenerating the corpora

Both lot 3 spikes generate their corpus from a script, and each `corpus/`
carried a `manifest.json` recording the generated file sizes and SHA-256
identities. Those manifests are kept, so a regenerated corpus can be verified
byte-identical to the measured one:

```bash
python spikes/raw-cap/corpus.py
```

`partial-mime` regenerates through `corpus.py` and drives a synthetic loopback
IMAP peer from `run.py`; the report notes that rewriting its fixtures with
Python's mail library would alter bytes and invalidate the oracle.

## Deliberately not archived

- **Build caches**, 1.7 GB: `target/lot2-spikes/` (950 MB, a shared Cargo
  `--target-dir`, no sources at all), `raw-cap/target/` (452 MB),
  `partial-mime/target/` (134 MB), `lot3-spikes/raw-cap/target/` (180 MB), and
  the `target/` of each calendar spike.
- **Generated corpora**, 384 MB — reproducible from `corpus.py` and verifiable
  against the kept manifests.
- **`partial-mime/results/`**, 30 binary extracts, 24 MB — outputs of `run.py`,
  with the findings recorded in its `REPORT.md`.
- **`lot2-idle-cancel/certs/`** — regenerated by `make-certs.ps1`; test
  certificates do not belong in a public repository.
- **The repository checkouts** carried by each worktree — ordinary git content
  at a58c1cf, already in history.
- **`target/parite/`** — 21 PNG captures, **deleted 2026-09-07 on the Chief
  Engineer's decision**. They were the last output of the manual parity bench
  `e2e/parite.mjs`, which commit b41d177 (PLAN-DC E1) retired on purpose along
  with the `ui_prototype.html` it compared against. The captures showed a
  prototype that no longer exists, in a comparison already closed. They were not
  regenerable, since the bench left the tree with its subject; git history keeps
  both the bench (b41d177^) and the prototype (import 9975a12) should the
  comparison ever be reopened.

No real account, credential, mailbox or field data appears in any of this: every
fixture and message is generated locally. The repository is public.
